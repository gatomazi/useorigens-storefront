# Use Origens — Guia de aplicação regional de cores

Este documento define como aplicar as paletas de Sul, Centro-Oeste e Norte no storefront da Use Origens.

Objetivo:

```text
mesma marca
+
mesmo sistema visual
+
identidade regional por cor, imagem e conteúdo
```

Não criar três sites visualmente desconectados.

A Use Origens continua sendo uma única marca.

As regiões ganham personalidade principalmente por:

- banners;
- fotografia;
- overlays;
- cores de apoio;
- seções editoriais;
- estados ativos;
- chips;
- detalhes gráficos;
- microinterações.

---

# 1. Princípio principal

A estrutura deve permanecer consistente entre todas as regiões.

Compartilhar:

- tipografia;
- grid;
- espaçamento;
- header;
- busca;
- cards de produto;
- PDP;
- comportamento mobile;
- motion;
- componentes;
- footer.

Regionalizar:

- paleta;
- banners;
- overlays;
- chips;
- estados ativos;
- CTAs secundários;
- seções editoriais;
- pequenos elementos gráficos.

A regra é:

```text
A COR IDENTIFICA A REGIÃO.
A ESTRUTURA IDENTIFICA A MARCA.
```

---

# 2. Regra de intensidade

Não usar todas as cores de uma região ao mesmo tempo.

Cada região deve operar com:

```text
1 cor principal
1 cor de apoio
1 cor de destaque
1 base neutra
```

Evitar:

- grandes áreas chapadas com muitas cores;
- cards de produto completamente coloridos;
- header inteiro colorido;
- footer inteiro colorido;
- degradês decorativos sem função;
- saturação alta em toda a página.

Preservar sensação:

```text
premium
editorial
contemporânea
regional
```

## Sensação desejada

```text
elegante
natural
sóbria
litoral + serra + cidade
```

Não comunicar Sul como:

```text
cinza
frio
chuva
melancolia
```

A região deve parecer viva.

Usar fotografia com:

- verdes naturais;
- céu azul;
- madeira;
- pedra;
- mar;
- vegetação;
- luz dourada moderada;
- arquitetura;
- natureza integrada à cidade.

---

## Aplicação visual

### Hero

Background:

- paisagem;
- sem produto embutido na imagem;
- sem texto na imagem;
- sem UI na imagem.

Overlay:

```text
claro
quente
ligeiramente bege
```

O overlay deve aproximar visualmente o banner do fundo da página.

Texto continua preto.

Detalhes podem usar:

```text
#4d543d
#d6ba8d
```

---

### Cards de produto

Manter predominantemente neutros.

Usar:

- fundo off-white;
- borda oliva muito suave;
- label dourado discreto;
- preço preto;
- hover oliva.

Não deixar o card parecer colorido demais.

---

### Seções editoriais

Exemplos:

```text
Fala daqui
DDD
Estados
Cidades
```

Podem usar:

- fundo oliva escuro + texto branco;
- fundo branco + detalhes dourados;
- imagem + overlay oliva sutil.

# 6. Paleta global da Use Origens

Elementos globais devem permanecer majoritariamente neutros.

## Global

```text
background principal = claro
texto principal = preto
surface = off-white
border = cinza muito suave
```

Não usar a paleta de uma região como base do `/`.

A raiz deve apresentar:

```text
Sul
Norte
Centro-Oeste
```

com cada bloco usando seus próprios acentos.

---

# 7. Hero regional — regra comum

Estrutura:

```text
PAISAGEM NO FUNDO
+
OVERLAY
+
TEXTO
+
BUSCA
+
PRODUTOS DO SITE
```

Importante:

O banner deve conter apenas:

```text
paisagem
```

Não inserir no arquivo da imagem:

- camisetas;
- estampas;
- logos;
- textos;
- busca;
- cards;
- botões;
- UI.

Produtos serão renderizados em overlay pelo próprio site.

---

# 8. Produtos no hero

Os produtos do hero devem ser tratados como parte da interface.

Usar:

```text
card editorial
```

com:

- fundo neutro;
- imagem do produto;
- nome;
- cidade/UF;
- preço.

O card pode usar detalhes da paleta regional.

Exemplo Sul:

```text
border: #d6ba8d
hover: #4d543d
```

Mas o fundo do card deve continuar neutro.

---

# 9. Busca

A busca continua sendo o elemento funcional mais importante.

A cor regional pode aparecer em:

- focus;
- underline;
- icon;
- border ativo;
- resultado selecionado.

Não mudar o fundo principal do input para cor regional.

---

# 10. Header

Header global:

```text
neutro
```

A região pode aparecer em:

- pequena tag;
- underline;
- label;
- estado ativo.

Não pintar o header inteiro.

---

# 11. Footer

Footer também deve continuar global.

A cor regional pode aparecer apenas em:

- linha;
- heading pequeno;
- link ativo;
- indicador.

---

# 12. Estados

Cards de estado são um dos melhores pontos para usar cor regional.

Exemplo Sul:

```text
base clara
mapa preto
linha dourada
hover oliva
```

Exemplo Centro:

```text
base bege
mapa terracota
linha ouro
hover verde
```

Exemplo Norte:

```text
base clara
mapa azul petróleo
linha dourada
hover verde
```

---

# 13. Chips e filtros

Usar a paleta regional principalmente em:

```text
active
hover
focus
```

Não colorir todos os chips ao mesmo tempo.

---

# 14. Seções editoriais

Aqui a cor pode aparecer com mais força.

Máximo recomendado:

```text
1 bloco forte por viewport
```

Exemplo:

```text
Sul
Fala daqui
fundo oliva

Centro
Campanha
fundo terracota

Norte
Editorial
fundo azul petróleo
```

Evitar sequência:

```text
verde
dourado
preto
verde
dourado
```

O ritmo visual deve continuar calmo.

# 16. Mobile-first

Como ~90% do tráfego é mobile:

validar cor primeiro em:

```text
375
390
430
```

A cor regional não pode:

- reduzir legibilidade;
- criar excesso visual;
- esconder produto;
- competir com busca;
- parecer banner promocional demais.

---

# 17. Acessibilidade

Todas as combinações de texto/background precisam atender contraste AA.

Não assumir que paleta bonita = contraste válido.

Validar:

- botões;
- chips;
- labels;
- links;
- overlays;
- texto sobre banner.

---

# 18. O que NÃO fazer

Não:

- usar todas as cores simultaneamente;
- aplicar paleta forte em cada seção;
- mudar tipografia por região;
- mudar estrutura de cards;
- mudar grid;
- mudar comportamento da busca;
- criar três design systems diferentes;
- transformar as páginas em “tema Sul / tema Norte / tema Centro”.

---

# 19. Implementação

Criar tokens regionais centralizados.

Exemplo conceitual:

```ts
REGION_THEME = {
  sul: {
    primary: "#4d543d",
    accent: "#d6ba8d",
    surface: "#ffffff",
    text: "#000000",
  },

  centroOeste: {
    primary: "#8c3b1f",
    secondary: "#3e5f3c",
    accent: "#e39a2d",
    surface: "#e6d6c3",
  },

  norte: {
    primary: "#234b50",
    secondary: "#3b7a57",
    accent: "#d4b873",
    surface: "#ffffff",
  },
}
```

Não precisa usar exatamente esse formato.

Evitar hex espalhado pelos componentes.

# 22. Critério final

A região deve ganhar personalidade suficiente para ser reconhecida.

Mas a pessoa ainda precisa perceber claramente:

```text
isto é Use Origens
```

A meta é:

```text
Use Origens
com sotaque regional
```

e não:

```text
três marcas visualmente separadas
```

Não fazer commit.
Não fazer push.
Parar para revisão visual depois da aplicação inicial no `/sul`.
